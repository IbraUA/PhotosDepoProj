# PhotoDrop

Сервіс для зберігання та роздачі зображень. Завантажуєш картинку — отримуєш пряме посилання на неї.
Метадані кожного зображення зберігаються в PostgreSQL; є сторінка зі списком, пагінацією та видаленням, а також скрипт резервного копіювання бази даних.

## Стек

- **Python** (стандартна бібліотека `http.server`, без фреймворків) + `Pillow` (перевірка зображень) + `psycopg 3` (робота з PostgreSQL)
- **PostgreSQL 17** — зберігання метаданих зображень
- **Nginx** — роздача статики (`/images/`, `/static/`) і проксування решти запитів на бекенд
- **Docker / Docker Compose** — контейнеризація, multi-stage build для мінімального розміру образу

## Структура проєкту

```
PhotoDrop/
├── app.py                     # Python-бекенд (маршрути, валідація, робота з БД, логування)
├── requirements.txt           # Залежності Python
├── Dockerfile                 # Multi-stage build бекенду
├── docker-compose.yml         # app + nginx + db, volumes
├── nginx.conf                 # Конфігурація Nginx
├── .env.example               # Шаблон змінних середовища (скопіювати в .env)
├── db/init.sql                # Створення таблиці images при першому запуску БД
├── templates/
│   ├── index.html             # Головна сторінка (завантаження)
│   └── images_list.html       # Сторінка списку зображень
├── static/                    # CSS/JS/іконки
├── scripts/
│   ├── backup.py              # Резервне копіювання БД (pg_dump)
│   └── load_test.py           # Тест паралельних завантажень
├── backups/                   # Резервні копії БД (створюється скриптом, не потрапляє в git)
├── images/                    # Завантажені зображення (Docker volume)
└── logs/                      # app.log (Docker volume)
```

## Запуск

Потрібен лише Docker (з Docker Compose).

1. Створи файл `.env` з шаблону і впиши свої значення (користувач, пароль, назва БД):

   ```bash
   cp .env.example .env
   ```

   (у Windows PowerShell: `Copy-Item .env.example .env`)

   `.env` обов'язковий: значень за замовчуванням немає, без нього проєкт не запуститься. Файл не потрапляє ні в git, ні в Docker-образ (`.gitignore`, `.dockerignore`).

2. Запусти:

   ```bash
   docker compose up --build
   ```

- Веб-інтерфейс: **http://localhost:8080**
- Список зображень: **http://localhost:8080/images-list**
- Бекенд напряму недоступний: порт 8000 відкритий лише всередині Docker-мережі, усі запити йдуть через Nginx
- Зображення: **http://localhost:8080/images/<ім'я_файлу>**

Зупинка: `Ctrl+C`, або `docker compose down` (додай `-v`, щоб видалити volumes — разом з ними зникнуть БД, зображення і логи).

## База даних

Таблиця `images` створюється автоматично при першому запуску контейнера `db` (скрипт `db/init.sql`):

| Поле | Тип | Опис |
|---|---|---|
| `id` | `SERIAL PRIMARY KEY` | Унікальний ідентифікатор |
| `filename` | `TEXT` | Згенерована сервером назва файлу (UUID + розширення) |
| `original_name` | `TEXT` | Оригінальна назва файлу від користувача |
| `size` | `INTEGER` | Розмір у байтах |
| `upload_time` | `TIMESTAMP` | Дата і час завантаження (за замовчуванням — поточний) |
| `file_type` | `TEXT` | Формат файлу (`jpg`, `png`, `gif`…) |

Метадані записуються **до** збереження файлу на диск: якщо запис у БД не вдався, файл не зберігається, а клієнт отримує `500`.

## Маршрути

| Маршрут | Метод | Опис |
|---|---|---|
| `/` | GET | Головна сторінка з формою завантаження |
| `/upload` | POST | Приймає файл (`multipart/form-data`, поле `file`). Формати: `.jpg`, `.jpeg`, `.png`, `.gif`. Максимальний розмір: 5MB. Перевіряється і розширення, і реальний вміст файлу (Pillow). Зберігає метадані в БД, повертає пряме посилання на зображення, або `400` / `500` з описом помилки |
| `/images-list?page=N` | GET | Таблиця завантажених зображень (назва з посиланням, оригінальна назва, розмір у КБ, дата, тип), від найновіших. По 10 на сторінку; кнопки «Попередня» / «Наступна» вимикаються на першій і останній сторінці. Якщо зображень немає — «Немає завантажених зображень» |
| `/delete/<id>` | POST | Видаляє запис з БД і файл з диску, після чого перенаправляє (`303`) назад на `/images-list`. `404` — якщо зображення з таким `id` немає, `400` — якщо `id` не число. Викликається кнопкою «Видалити» у списку |
| `/images/<ім'я_файлу>` | GET | Віддає завантажене зображення (обробляється Nginx) |
| `/static/...` | GET | CSS/JS/іконки інтерфейсу (обробляється Nginx) |

## Логування

Усі дії — завантаження, видалення, резервне копіювання — записуються в `logs/app.log` (Docker volume `logs`) у форматі:
```
[Дата час] Дія: повідомлення
```

Переглянути останні записи:
```bash
docker compose exec app tail -n 20 logs/app.log
```

## Резервне копіювання

### Створення бекапу

Контейнери мають бути запущені. Запуск з будь-якої папки (скрипт сам переходить у корінь проєкту):

```bash
python scripts/backup.py
```

Скрипт:
1. виконує `pg_dump` всередині контейнера `db` (користувач і назва БД беруться зі змінних середовища контейнера, тобто з `.env` — у скрипті нічого не захардкоджено);
2. копіює дамп з контейнера в папку `backups/` з датою і часом у назві, наприклад `backups/backup_2026-10-06_152835.sql`;
3. записує результат (успіх або помилку) в `logs/app.log`.

Папка `backups/` створюється автоматично і не потрапляє ні в git, ні в Docker-образ.

### Відновлення з бекапу

Дамп містить `CREATE TABLE`, тому відновлення виконується в **порожню** базу (інакше будуть помилки «already exists» і дублікати даних).

1. Видали поточну таблицю:

   ```bash
   docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "DROP TABLE IF EXISTS images;"'
   ```

2. Скопіюй потрібний бекап у контейнер:

   ```bash
   docker compose cp backups/backup_2026-10-06_152835.sql db:/tmp/restore.sql
   ```

3. Виконай його:

   ```bash
   docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -f /tmp/restore.sql'
   ```

> У Windows PowerShell не використовуй перенаправлення `> backup.sql` / `< backup.sql`: PowerShell 5 змінює кодування файлу (UTF-16), і дамп може не відновитися. Тому скрипт і інструкція працюють через `pg_dump -f` / `psql -f` всередині контейнера та `docker compose cp`.

### Автоматичний запуск за розкладом

Скрипт робить один бекап за запуск, тому розклад задається засобами системи:

- **Windows** — Планувальник завдань (Task Scheduler): нове завдання → дія «Запуск програми» → `python`, аргумент — повний шлях до `scripts\backup.py`.
- **Linux / macOS** — cron, наприклад щодня о 03:00:

  ```
  0 3 * * * cd /шлях/до/PhotoDrop && python3 scripts/backup.py
  ```

## Тестування паралельних завантажень

```bash
pip install requests
python scripts/load_test.py
```

Надсилає 10 одночасних POST-запитів на `/upload` і вимірює час — перевіряє, що бекенд (`ThreadingHTTPServer`) реально обробляє запити паралельно.
